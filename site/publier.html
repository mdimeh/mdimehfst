Logique éditoriale

Le site repose sur quatre fonctions : informer · écouter · expliquer · rendre compte. Chaque publication doit relever d'une de ces fonctions et être classée par catégorie.

Cinq engagements de redevabilité — référence éditoriale.

Rythme recommandé

  • Hebdomadaire : 1 compte rendu de terrain + 1 actualité.
  • Bimensuel : 1 analyse longue (rubrique Analyses).
  • Trimestriel : 1 rapport public de redevabilité.
  • Au fil de l'eau : communiqués, interventions médias, dossiers urgents.

Catégories disponibles

Terrain · Conseil communal · Communiqués · Analyses · Quartiers · Médias · Femmes · Jeunes · Redevabilité. Une seule catégorie principale par article.

Comment ajouter un article (FR)

1

Ouvrir le fichier data/articles.json

Ce fichier est un tableau d'articles. Chaque entrée respecte la structure ci-dessous.

2

Ajouter une entrée en haut du tableau

{
  "id": "rencontre-citoyenne-anza-2026-05-12",
  "title": "Rencontre citoyenne à Anza — services de proximité",
  "date": "2026-05-12",
  "category": "Terrain",
  "tags": ["Anza", "quartiers", "éclairage"],
  "image": "assets/news/anza-2026-05-12.jpg",
  "excerpt": "Compte rendu de la rencontre du 12 mai à Anza : trois priorités identifiées.",
  "content": "Texte complet de l'article, en plusieurs paragraphes séparés par des sauts de ligne.\n\nDeuxième paragraphe.",
  "author": "Dr. Raja Messou",
  "featured": false
}

id doit être unique, en minuscules, avec des tirets. image est facultatif : si vide, un visuel généré sera utilisé. featured: true met l'article « à la une ».

3

Ajouter l'image (facultatif)

Déposez le fichier dans assets/news/ (formats JPG ou PNG, largeur recommandée 1600px). Renseignez le chemin relatif dans le champ image.

4

Publier la version arabe

Dupliquez l'entrée dans data/articles.ar.json, en utilisant le même id et la même date, et en traduisant titre, résumé, contenu, tags et catégorie.

5

Mettre en ligne

Si vous éditez en local : sauvegardez les fichiers, poussez le commit (git push). Si vous éditez directement sur GitHub : cliquez « Commit changes » sur chaque fichier modifié.

Mettre à jour l'agenda

Fichier : data/events.json (FR) et data/events.ar.json (AR).

{
  "id": "permanence-anza-juin",
  "title": "Permanence citoyenne — quartier Anza",
  "date": "2026-06-15",
  "time": "16:00 — 19:00",
  "place": "Maison des jeunes, Anza",
  "type": "Permanence",
  "quartier": "Anza"
}

Mettre à jour les dossiers terrain

Fichier : data/quartiers.json (FR) et data/quartiers.ar.json (AR).

Statuts utilisables : Signalé · Reçu · En cours · Suivi · Réponse reçue.

Recevoir les messages des citoyens

Par défaut, les formulaires (réclamation, contact, newsletter) sont enregistrés dans le navigateur et consultables sur la page Admin (mot de passe par défaut : agadir2026, à changer dans assets/script.js via la variable RM_ADMIN_PASSWORD).

Pour recevoir réellement les messages sur un email ou une base partagée, branchez un webhook :

  1. Créez un endpoint gratuit chez Formspree, Getform, ou Netlify Forms.
  2. Ajoutez l'attribut data-endpoint="https://votre-webhook" sur chaque balise <form data-form="…"> dans reclamations.html, contact.html et l'index.html (newsletter).
  3. Le script POSTera automatiquement chaque soumission au format JSON.

Bonnes pratiques éditoriales

  • Un titre court (≤ 70 caractères), concret, jamais slogan.
  • Un résumé de 1 à 2 phrases qui explique le pourquoi.
  • Toujours préciser le quartier dans les tags si pertinent.
  • Ajouter au moins une photo de terrain par compte rendu.
  • Toute publication politique est accompagnée d'un acte concret (intervention, dossier, rendez-vous).
  • Pas de jargon, pas d'agression : sérieux, accessible, pédagogique.
